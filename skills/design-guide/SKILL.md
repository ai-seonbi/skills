# AI 디자인 작업 가이드

디자인 방향이 아직 정해지지 않았거나, 같은 기준으로 여러 시안을 비교·수정·재사용하고 싶을 때 쓴다. 특정 앱, 명령어, 파일 위치를 전제하지 않는다. 단발 이미지 생성, 이미 확정된 화면의 단순 구현, 사람의 선택을 대신하는 자동 미학 판정에는 쓰지 않는다.

## 경계

- 사람은 방향을 고른다. 이유를 말했으면 그대로 기록하고, 이유가 없으면 `이유 제공 안 됨`으로 남긴다. AI의 추천은 선택을 위한 재료다.
- 공개 접근 가능한 자료만 조사한다. 로그인 우회, 세션 재사용, 접근 제한 회피를 하지 않는다.
- 레퍼런스는 기본적으로 링크와 해석만 기록한다. 이미지·스크린샷을 저장하거나 재배포하려면 이용 조건과 라이선스를 먼저 확인한다.
- 사용자가 쓰기를 요청한 범위 밖의 파일·제품 UI·외부 서비스는 바꾸지 않는다.
- 예시·초안·재현은 실제 사용자 선택이나 실행 결과처럼 말하지 않는다.

## 작업 순서

1. 시작할 때 [starter-brief.md](references/starter-brief.md)를 열어 아는 정보부터 확인한다. 이번에 결정할 것과 보는 사람이 불명확할 때만 한 번에 필요한 질문을 한다.
2. 기존 결과물·스타일 규칙·확정 기록이 있으면 먼저 읽어 유지할 제약을 추린다. 조사할 때는 [process.md](references/process.md)의 단계를 따라 레퍼런스마다 관찰, 가져올 점, 피할 점, 적용 가설을 분리한다.
3. 아직 방향을 고르지 않았으면 갈리는 축을 하나 좁힌 뒤 같은 내용의 2~3안을 제안한다. 파일 작성과 브라우저 확인이 가능하면 외부 의존 없는 자체 포함 HTML 비교 파일로, 옵션을 한 화면에서 보이게 만든다. 그 환경이 아니면 비교용 프롬프트·수동 검토 순서를 제공하고 렌더 검증을 하지 못했다고 보고한다.
4. 이미 고른 방향의 작은 수정이면 새 대안을 강제하지 않는다. 유지할 요소와 바꿀 요소를 분리하고, 전후를 나란히 비교할 수 있게 만든다. HTML을 만들 수 있으면 브라우저에서 직접 시각 검토한 뒤 전달한다.
5. 사람이 고른 안과 이유를 [decision-record.md](references/decision-record.md)에 기록한다. 이유가 없으면 `이유 제공 안 됨`으로 남기고 AI의 해석과 섞지 않는다. 요청 문장 예시는 [request-examples.md](references/request-examples.md)에서 연다.
6. 결과를 보기 전 [qa-recovery.md](references/qa-recovery.md)의 시각 검토를 한다. 다음 작업에는 확정한 기록만 입력으로 재사용한다.

## 완료 전 확인

- 레퍼런스의 사실과 내 해석이 구분되어 있다.
- 새 방향을 고른 경우 선택지는 둘 이상이었고, 사람이 고른 안이 남아 있다. 기존 선택의 작은 수정에는 이 조건을 다시 적용하지 않는다.
- 사람의 이유는 제공된 경우만 기록하며, 없으면 `이유 제공 안 됨`으로 표시한다.
- 수정 범위와 유지할 요소가 분명하다.
- 작은 화면과 큰 화면에서 글자, 대비, 잘림, 겹침을 확인했다.
- 파일·브라우저 환경에서 HTML을 만들었다면 실제 브라우저 시각 검토를 마쳤다. 환경이 없었다면 렌더 검증을 하지 못했다고 보고했다.
- 다음 작업에 넘길 기준은 확정된 선택에서만 추렸다.

## 실패 신호와 대응

| 신호 | 대응 |
| --- | --- |
| 레퍼런스 하나를 그대로 복제하려 한다 | 특징을 추상화하고 링크·해석만 남긴 뒤, 새 내용과 제약으로 다시 제안한다. |
| AI의 추천을 사람의 결정으로 기록하려 한다 | 기록을 `AI 제안`과 `사람이 확인한 선택`으로 나누고, 선택 이유를 묻는다. |
| 한 안만 내고 바로 적용하려 한다 | 같은 내용의 대안 1개 이상을 먼저 만든다. |
| 기존에 고른 방향의 작은 수정에 다시 여러 안을 강제한다 | 유지·변경 요소와 전후 비교만 제시한다. |
| 파일·브라우저가 가능한데 텍스트 설명만 준다 | 외부 의존 없는 HTML 비교를 만들고 실제 브라우저에서 확인한다. |
| 파일·브라우저가 없는데 렌더 검증을 했다고 말한다 | 비교 프롬프트와 수동 확인 순서를 제공하고, 미검증 사실을 보고한다. |
| 시안은 나왔지만 읽기 어렵거나 요소가 겹친다 | 검토를 멈추지 말고 [qa-recovery.md](references/qa-recovery.md)의 원인별 수정 순서를 따른다. |
| 대상·사용자·제약이 비어 있다 | 그럴듯하게 가정하지 말고 짧은 의뢰서의 빈칸부터 확인한다. |
| 라이선스나 접근 권한이 불분명하다 | 에셋 저장·재배포를 하지 않고 링크와 관찰만 쓴다. |

## 종료 조건

- 성공: 사람의 선택과 제공된 이유 또는 `이유 제공 안 됨`이 남아 있고, 비교·수정·시각 검토 결과와 다음 작업에 쓸 기준이 남아 있다.
- 기권: 핵심 의뢰, 선택, 권한, 라이선스가 확인되지 않아 신뢰할 수 있는 결과를 만들 수 없다.
- 에스컬레이션: 기존의 확정 기준과 새 요청이 충돌하거나, 권한자가 선택을 보류하면 사람의 결정을 요청한다.
