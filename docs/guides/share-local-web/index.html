네 가지 방법

CLOUDFLARE

Quick Tunnel

로그인 없이 공개 링크를 빠르게 만들고, 컴퓨터와 터널을 켜둔 동안만 보여줄 때 씁니다.

brew install cloudflared
cloudflared tunnel --url http://localhost:18766
  • URL을 아는 사람은 누구나 접근
  • Control+C 뒤 새 접속 실패 확인
  • 개발·시험 용도이며 운영용 SLA 없음
Cloudflare 공식 문서
TAILSCALE

Serve

같은 tailnet에 연결되고 권한이 있는 기기만 로컬 서비스를 열게 할 때 씁니다.

tailscale serve --https=8443 \
  http://127.0.0.1:18766
  • 상대방에게 Tailscale와 권한 필요
  • 일반 고객에게 보낼 공개 링크가 아님
  • 종료 후 tailscale serve status 확인
Tailscale Serve 공식 문서
TAILSCALE

Funnel

Tailscale이 없는 사람도 일반 브라우저에서 로컬 서비스를 열게 할 때 씁니다.

tailscale funnel --https=8443 \
  http://127.0.0.1:18766
  • 인터넷에 공개되는 URL
  • 내 서비스와 Funnel이 실행 중이어야 함
  • 작업 뒤 설정 제거 여부 확인
Tailscale Funnel 공식 문서
VERCEL · HOSTING

외부 서버에 배포

내 컴퓨터를 꺼도 계속 열리는 페이지가 필요할 때 씁니다. 터널과 달리 파일을 외부 서버에 올립니다.

npm install -g vercel
vercel deploy public --prod --yes
  • 로컬 서버를 끈 뒤 공개 URL 새로고침
  • 프로젝트의 배포 보호 설정 확인
  • 다른 호스팅 서비스도 같은 범주
Vercel 공식 문서

명령은 2026-09-21 macOS 실습을 기준으로 합니다. Windows·Linux는 각 공식 설치 문서를 따라야 합니다. Serve·Funnel의 두 번째 물리 기기 검증은 아직 완료되지 않았습니다.

성공과 종료를
둘 다 확인하세요

1. 로컬 확인공유하기 전에 localhost에서 올바른 페이지와 포트가 열리는지 확인합니다.
2. 다른 환경 확인같은 브라우저 탭이 아니라 다른 기기나 권한이 없는 환경에서 접속합니다.
3. 공개 범위 확인Serve인지 Funnel인지, 공개 배포인지 화면의 주소와 권한으로 확인합니다.
4. 종료 확인프로세스를 끈 뒤 새 접속이 실패하는지, 임시 설정이 제거됐는지 확인합니다.
